## Hosted repair loop

The first hosted SDK attempt returned 503 while the public workflow and Gemini agent worked. Added only private-safe error codes, exception class names and process signals to server diagnostics; vendor messages, credentials and source text are excluded. A second hosted check identified `SIGILL` (unsupported CPU instruction).

The SDK's hnswlib dependency defaults to compiling for the build host CPU. The Docker SDK stage now sets `HNSWLIB_NO_NATIVE=1` so it can run on a different CPU; numerical worker threads are also bounded to one. The rebuilt release passed the real hosted SDK check. The upstream flag is defined in [hnswlib 0.8.0 setup](https://github.com/nmslib/hnswlib/blob/v0.8.0/setup.py).

## Remaining limits

FalkorDB Cloud is **not connected**. Its free instance was Running / Healthy, but the connection had TLS disabled and the Modify dialog exposed no TLS option. [Official pricing](https://www.falkordb.com/plans/) listed TLS unavailable on Free. No paid plan was activated and no Cloud database credentials were transmitted to that plaintext endpoint. Remote TLS verification remains enforced.

The approved free Render deployment runs FalkorDB on loopback inside the app container. It can sleep, and restarts or redeployments reset graph updates and sessions. It is a synthetic demo, not durable production hosting. Model free quota can run out; there is no paid or local-model fallback. No production load test, high-availability claim or external security assessment is made.
